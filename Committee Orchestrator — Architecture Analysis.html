Step 0 through step 8

How information moves

Two things govern the shape of this diagram. The eight data agents run at the same time and cannot see one another. Everything after them runs in order, and each stage sees everything produced before it.

context flow report path veto short-circuit Teal boxes run concurrently · brass boxes run in order

Isolation in step 1

The eight data agents receive identical context — resolved project metadata, canonical metrics with an as-of date, and any standing contradiction warnings — and nothing else. They cannot read each other's output.

This makes convergence meaningful. Eight agents that read one another produce one opinion restated eight times; agreement between agents that cannot see each other is evidence.

Accumulation after

From step 4 onward the context grows monotonically. The Maturation Scorer sees the whole data layer, the Risk Officer sees that plus maturation, and so on down the chain. The Chair sees everything every agent produced.

Tool-calling loop

Each agent runs up to fifteen rounds of call, tool use, result, call — deciding for itself when it has enough to emit structured JSON. An agent that exhausts its rounds returns an explicit error rather than a partial answer.

Two reconciliation passes

The first pass compares the data layer against itself, before synthesis. The second runs after the report exists and checks the report's own figures — the assembling agent is otherwise the only one whose internal consistency nothing tests.

A figure is only reported as contradicted when two or more distinct agents assert incompatible values. A lone dissenter is almost always measuring something adjacent and labelling it loosely.

Sources

Price, token info and market data come from CoinGecko. TVL and protocol fees come from DeFiLlama. Klines, order-book depth and computed technical levels come from exchange data. Open-web search runs through Brave, and social retrieval through the X API.

The two toolless seats

The Report Writer and the Chair hold no domain tools at all. Both exist to reason over what the committee already produced, and giving either one a live data feed would let it introduce a figure no analyst ever vouched for.

Deterministic ordering

Tool definitions render at position zero of the cached prompt prefix, ahead of the system prompt, so the array order is fixed and deduplicated by first occurrence. An unordered set here silently defeats prompt caching across worker processes.

Score first

The weighted score is computed before the Chair deliberates, and the Chair is shown the resulting band. Divergence between the band and the Chair's decision is recorded as divergence; a contradiction — a decision the band cannot support at all — is recorded separately. They are different failures and do not share a field.

Bands

75 and above reads BUY, 60 and above WATCH, below 60 PASS. A Risk Officer veto overrides everything to VETO, and no downstream agent has a mechanism to lift it.

Missing agents

When an agent fails, its weight is dropped and the remaining weights renormalise. A run therefore still scores with a degraded data layer, and the report records which seats were empty.

Adversarial design

Mechanisms of contention

A committee that agrees with itself is a single analyst with extra latency. Five mechanisms exist to force disagreement into the record rather than letting it dissolve — three argumentative, two arithmetic.

Unilateral veto

The Risk Officer can veto regardless of every other score, on six enumerated triggers. It is the only unilateral power in the system and it is final — no later stage can lift it, and the Chair has no override mechanism.

Mandated dissent

The Devil's Advocate is instructed to find reasons not to invest and to classify each weakness as fatal, manageable, or noise. It carries no score weight, so it cannot be neutralised by being outvoted — its output reaches the Chair as argument rather than as a number.

Independent review

Ray Dalio runs after the report is written, using different mental models, and may explicitly disagree with the committee. The Chair must adjudicate all three perspectives and record how each conflict was resolved in the adjudication trace.

Within-run reconciliation

Figures are extracted from every agent's prose and compared inside a single evaluation. Where two or more distinct agents assert incompatible values for the same metric, entity and period, the conflict is surfaced to the Chair before it decides.

A binding rule keeps this honest: a figure governed by a nearer noun — a buyback, a treasury balance, a staked amount — does not bind to a metric inferred from a nearby time window.

Cross-report sweep

Every ten reports, or every thirty days, a sweep compares all persisted reports for figures that cannot all be true. Findings are verified, then written into the committee's knowledge base as warnings that reach future evaluations through their shared context.

Platform

Infrastructure

FastAPI on port 8100, Postgres 16 with pgvector, Redis, Docker Compose on a Hetzner VPS reached over Tailscale. Claude primary with an OpenAI fallback. Notion write-back for project tracking, and a Telegram bot as the human surface.

Prompt caching

The system prompt is ordered stable-first with volatile content behind an explicit boundary, and tool arrays are deterministically ordered so a cache entry written by one worker is readable by another.

Forward-only migrations

An advisory lock and a checksum ledger. init.sql runs only on an empty volume, so schema changes reach production through the migration runner or not at all.

Signposts ledger

A WATCH is falsifiable only if its triggers are recorded. The Chair emits signposts and a review date, and both are persisted against the evaluation.

Calibration loop

Date-anchored checkpoints against realised outcomes, using true historical pricing with recorded provenance. Future target dates are refused rather than silently accepted.

Delta reporting

Re-evaluating a project re-runs what moves — token, socials, governance — and reports section 25 against the previous evaluation rather than starting from nothing.

Queue and confirmation

The bot confirms the resolved project before spending, queues jobs with JSON persistence across restarts, and carries no read timeout on the evaluation call.

Semantic retrieval

Notion notes are chunked and embedded into pgvector. The similarity threshold is derived from the measured noise ceiling of the embedding model rather than set by convention.

Report surfaces

Reports render as escape-first server-side HTML with no client JavaScript and a default-src 'none' policy, and as Markdown for delivery through the bot.
