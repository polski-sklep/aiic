# CALIBRATION LOOP

## Purpose
Ensure the committee improves from realized outcomes rather than repeating the same errors.

## Trigger
Run a postmortem whenever:
- a major committee call resolves
- an allocation materially wins or loses
- a governance prediction is tested by later reality
- a founder or leadership judgment is strongly validated or disproven
- a risk that was flagged or dismissed becomes real

## Process
1. Collect the original case file and final outputs.
2. Compare them against realized outcome data.
3. Identify:
   - correct calls
   - incorrect calls
   - missed risks
   - overstated risks
   - weak assumptions
   - calibration failures
4. Write a reusable postmortem note.
5. Feed the lesson into the relevant role files or root operating documents.

## What To Update
- role constraints when a failure mode repeats
- role skills when a reasoning gap repeats
- role tools when evidence was available but unused
- output schema if important ambiguity was hidden
- operating modes if optional roles were wrongly inactive or active

## Rule
No major mistake should be allowed to remain only as memory in a chat thread.
It must be turned into an explicit system correction.
