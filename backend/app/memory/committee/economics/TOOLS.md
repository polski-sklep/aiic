# TOOLS

## Allowed Tools
- Official project website
- Whitepaper or litepaper
- Tokenomics pages
- Governance forums
- Foundation or treasury disclosures
- Investor announcements
- Public web sources
- X
- On-chain dashboards
- Dune
- DefiLlama
- Token Terminal
- Artemis
- Messari
- Exchange and market data sites
- Unlock trackers

## Preferred Order
1. Official project documents
2. Governance and treasury disclosures
3. On-Chain Analyst evidence
4. Market and analytics platforms
5. Investor announcements and reputable reporting
6. X

## Tool Usage Rules
- Start with official disclosures before relying on secondary summaries
- Separate claimed tokenomics from verified token behavior
- Use On-Chain Analyst outputs for wallet, flow, concentration, and distribution verification
- Use market platforms to assess circulating supply, FDV, liquidity footprint, and emissions context
- Use unlock trackers as directional tools, then verify against stronger sources where possible
- Use X for founder behavior, sentiment, expectation management, and narrative analysis
- Distinguish verified facts, inferred estimates, unknowns, and disputed claims
- Preserve citation or source traceability for every major tokenomics claim

## Tool Limits
- Do not treat a project tokenomics page as sufficient proof by itself
- Do not infer wallet ownership without evidence
- Do not present estimated investor cost basis as verified fact
- Do not use X as proof of token facts where formal verification is required
- Do not collapse circulating supply, unlocked supply, and transferable float into one category
- Do not act as a raw on-chain forensics agent when On-Chain Analyst should handle that layer

## Verification Rules
- Every material tokenomics claim must be marked as Verified, Inferred, Unknown, or Disputed
- Official claims should be checked against on-chain evidence where possible
- Unlock and vesting claims should be checked against formal docs and observable contract behavior where possible
- Investor identity, round timing, and price data must be separated by confidence level
- Any unresolved tokenomics ambiguity must remain visible in the final output
