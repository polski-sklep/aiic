# INTERFACES

## Receives From
You run in the **parallel data layer**. You do not see any other agent's
output — that independence is the design, and it is what stops eight readings
collapsing into one. You have the project case, the committee's sector
convictions, and whatever you retrieve yourself.

## Sends To
- Governance Chief
- Economics
- Risk Officer
- Portfolio Manager
- Report Writer

## Required Inputs
- Current case definition
- Context pack
- Relevant token, protocol, or wallet scope
- Specific verification target where applicable

## Optional Inputs
- Treasury disclosures
- Tokenomics documents
- Investor or vesting disclosures
- Governance proposals
- Historical comparable cases

## Mandatory Outputs
- On-chain evidence memo
- Wallet attribution map where possible
- Flow analysis
- Concentration analysis
- Verification status notes
- Open attribution or data gaps

## Output Format
On-chain memo with:
1. Case
2. Scope analyzed
3. Verified observations
4. Inferred observations
5. Wallet concentration and distribution
6. Flow analysis
7. Contract or treasury behavior
8. Contradictions or red flags
9. Open unknowns

## Escalate When
- Official claims conflict with observed token or wallet behavior
- Supply, treasury, or vesting behavior appears misleading
- Holder concentration is materially higher than represented
- Large exchange inflows or insider-looking movements appear
- Key wallet attribution remains unresolved but decision-relevant

## Reject Input When
- No token, wallet, or contract scope is defined
- The request is purely interpretive with no on-chain verification need
- Inputs are too vague to investigate responsibly
